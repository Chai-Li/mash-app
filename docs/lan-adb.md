# 局域网 ADB 连接（本地构建版）

此修改基于上游 Mash 0.30.0（`f4388a9436bf3a7433527b69954f8f84e2bdbc1d`），源代码采用 MIT 许可证。它为“手动添加设备”增加主机地址，并让设备列表刷新保留已建立的网络连接。

## 连接设备

1. 让运行 Mash 的电脑和 Android 设备处于可互通的局域网，开启设备的网络 ADB。
2. 在 Mash 右下角打开“选择设备”，点击“手动添加”。
3. 输入设备的主机/IP 和 ADB 端口，例如主机 `192.168.1.100`、端口 `5555`，点击“添加”。
4. 在返回的设备列表中点击对应预览，选中该设备。选中地址会保存，后续状态检查和任务使用该地址。

主机也支持域名、IPv6（例如 `fd00::1234` 或 `[fd00::1234]`）；端口单独填写。默认 `127.0.0.1:5555` 仍用于本机模拟器。刷新设备列表不会再重启整个 ADB 服务。

连接成功后，按应用提示下载上游 CV 运行时与资源，再使用截图、视频流及自动化功能。Windows CV 原生运行时仍使用上游清单指定版本，无需重编译。

## 如何开启网络 ADB

设备已经监听 ADB TCP 端口时，直接填写它提供的地址即可。远程模拟器需要把 ADB 服务开放在局域网可访问的地址；只监听远程电脑 `127.0.0.1` 的端口无法直接从另一台电脑访问。

普通 Android 手机可先通过 USB 授权，然后执行 `adb -s <USB设备序列号> tcpip 5555`，再使用手机的 Wi-Fi IP 连接。设备或系统策略可能不支持此方式。

Android 11 及以上“无线调试”如果要求配对，先使用本构建附带的 `resources/adb/adb.exe pair <手机IP>:<配对端口>`，按提示输入配对码；然后在 Mash 填写无线调试首页显示的**连接端口**。配对端口和连接端口通常不同。本次改动提供连接入口，配对仍通过 ADB 完成。

仅在可信局域网启用网络 ADB，不要把调试端口映射到公网。

## 排查

- 连接超时或被拒绝：核对 IP、连接端口、设备是否仍开启网络调试，以及防火墙是否允许该端口。
- `unauthorized` 或认证失败：确认设备上的调试授权；无线调试则先完成配对。
- 已连接但没有预览：解锁设备后刷新，确认 ADB 能截屏。
- 远程 MuMu 开启应用保活且有多个显示屏：上游需要本机 MuMu SDK 来识别独立游戏显示屏。可先关闭远程 MuMu 的应用保活，让游戏显示在默认屏幕；本次改动不提供远程 MuMu SDK。

## 构建

安装贡献指南中的 Windows 构建依赖后：

```powershell
pnpm install --frozen-lockfile
./scripts/windows/build-windows.ps1 -Unsigned
```

安装包位于 `src-tauri/target/release/bundle/nsis/`。这是本地修改、未签名版本；上游更新可能覆盖此功能，请保留源码和安装包。

新增校验与等待上限：主机和端口分开填写，端口为 1–65535；手动连接最多等待 10 秒；列表查询与重连使用有界等待，旧地址不可达时仍可选择其他在线设备。无额外设备类型或网段限制。此交付按要求不进行实机连接测试。
